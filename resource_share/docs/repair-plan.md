# 1.0.5 修复准备

## 功能范围

同一公会的全部据点共享全部据点储物箱中的所有物品。不得硬编码石头、10 个、两个据点或物品白名单；物品实际用途遵守原生配方与消耗规则。共享的是可用库存和真实扣料能力，不能通过复制物品实现。

应盘点当前版本不同储物箱实现，记录覆盖情况；远处及本次进档后未访问的据点需要验证，不能仅凭两个已加载箱子的测试宣称支持全部据点。

## 实施顺序

1. 基于原始提交建立修复分支，保存可回退基线。
2. 补充受限诊断：记录注册调用失败、基地归属与材料查询结果；避免高频全世界扫描或持续输出完整物品数据。
3. 验证当前版本的材料查询、扣料和配方计数接口。参考 PR #5 的原生过滤适配，但不能未经验证复制其偏移或认定普通 Lua RegisterHook 能拦截所有原生内部调用。
4. 按接口证据决定保留 Lua 还是引入 C++ 模块。若引入原作者 C++ 代码，带入其 MIT 许可证，并使用与现有 UE4SS 相符的构建环境。
5. 限定共享范围为同公会、当前有效基地与有效箱子；处理拆箱、基地变化和世界切换后的过期对象。
6. 修复同时覆盖菜单计数、配方不足判定和真实扣料，避免仅改变显示造成免费建造或重复扣料。
7. 备份安装文件后部署测试；记录实际游戏版本、UE4SS 版本、提交号、测试步骤和观察结果。

## 游戏验收

| 场景 | 预期 |
| --- | --- |
| 三个或更多据点分别存放不同物品 | 每个据点都能查询并按原生配方使用其他据点的物品 |
| 木材、矿石、金属、制作素材等多种物品，含拆分在多个箱子的同类物品 | 各物品总量正确，无硬编码物品白名单；跨箱扣料准确 |
| 当前版本各类储物箱 | 逐类记录并验证共享覆盖，不能仅测试一种箱子 |
| 远处及本次进档后未访问的据点 | 验证资源可用性；若受加载限制，记录为待解决问题 |
| A 有 10 石头；玩家及 B 没有石头（最小示例） | B 建造菜单正确计入 10 个 |
| B 建造消耗 N 个石头的建筑（N ≤ 10） | A 剩余 10 − N；没有物品复制或重复扣除 |
| 成本超过公会现有总量 | 正常提示不足，不能免费建造 |
| 工作台和生产设施 | 配方图标、可制作数量和实际消耗一致 |
| B 为新建且无箱子的基地 | 可使用同公会已有基地材料 |
| 新建箱子、修改库存、拆除箱子 | 及时刷新，拆除后没有幽灵库存 |
| 传送、返回标题、重新进档 | 无旧对象引用、错误合并或崩溃 |
| 快速堆叠和物品检索设备 | 原有物品整理行为正常 |
| 可构造不同公会场景时 | 不读取或扣除其他公会资源 |

当前没有执行这些修复后验收项目，不应勾选为通过。
